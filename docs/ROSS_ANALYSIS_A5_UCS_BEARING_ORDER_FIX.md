## Root cause

Frozen `Rotor.__init__` stable-sorts `bearing_elements` by `el.n` before
`run_ucs` removes seals and takes the first physical bearing. RotorStudio
`python/src/drm_core/solver/ucs_backend.py::_validate_model` formerly returned
the validated supports in insertion order. `execute` then used that order
both for native node marshaling and `bearing0=supports[0]`.

Consequently the wrong original bearing could own the speed/frequency axis,
Kxx/Kyy curve, raw coefficient-family equality test, intersections and the
subsequent critical-point modal solves. This defect is distinct from the
undamped temporary UCS rotor: its supports all receive the same isotropic k.
